# 짐메이트 (GymMate) — 설계 문서

**작성일:** 2026-09-02
**저장소:** `헬스장출석어플`
**상태:** 초안 (사용자 리뷰 대기)

---

## 1. 목적

친한 친구 소그룹(5~20명)이 서로의 헬스장 출석을 공유하고, 개인 주간 목표 달성률을 서로 확인하며 동기 부여하는 웹앱.

## 2. 핵심 컨셉

- **PWA 웹앱** — 링크로 뿌리고 각자 iPhone 홈화면에 추가
- **위치 기반 체크인** — 등록한 헬스장 100m 이내에서만 성공. 실패 시 사진(카메라 촬영만) 인증
- **주 N회 고정 목표** — 개인별로 설정, 주간 달성률로 서로 비교
- **초대 링크로 그룹 참여** — 카톡 등으로 링크 뿌리기

## 3. 대상 사용자 / 규모

- 앱 개발자와 친한 친구/운동 메이트 소그룹
- 초기 예상: 그룹 1~3개, 총 사용자 10~30명
- 무료 티어(Supabase, Vercel) 내에서 유지 가능한 규모

---

## 4. 기술 스택

| 계층 | 선택 | 이유 |
|---|---|---|
| Frontend | **Next.js (React) + PWA** | 예제 압도적으로 많음, Vercel 자동 배포 궁합, iPhone 홈화면 추가 지원 |
| Backend | **Supabase** | Auth(매직링크) + Postgres + Storage + RLS 한 곳. Seoul 리전 있음 |
| 외부 API | **Naver 지역검색** | 한국 헬스장 검색 정확도 최상, 무료(일 30만 요청) |
| Hosting | **Vercel** | GitHub push → 자동 빌드/배포. 무료 |
| 저장소 | **GitHub** | 소스 관리 + Vercel 트리거 |

## 5. 화면 구조 (4개 탭)

```
┌─────────────────────────────────────────┐
│ [오늘]  [캘린더]  [그룹]  [설정]         │
└─────────────────────────────────────────┘
```

### 5.1 오늘 탭
- "오늘 헬스 감" 큰 버튼 (탭 = 체크인 흐름 시작)
- 오늘 이미 체크인한 경우: 메모/사진 조회 및 수정
- 이번주 진행: 도트 형태로 `●●●○○○○ (3/5회)`

### 5.2 캘린더 탭
- 월별 캘린더 뷰
- 체크인한 날짜에 도트 표시
- 날짜 탭 → 그날 메모/사진 조회

### 5.3 그룹 탭
- 그룹 스위처 (여러 그룹 소속 시 드롭다운)
- **"초대 링크 복사" 버튼** (탭 → 클립보드에 복사 → 카톡 등에 붙여넣기)
- 멤버 리스트 + 각자 이번주 달성률 %
- 최근 활동 피드 (누가 언제 어떤 방식으로 체크인)
- (방장만 보임) 멤버 옆 "…" 메뉴 → 추방
- (방장만 보임) "새 초대 링크 발급" (기존 링크 무효화)

### 5.4 설정 탭
- 프로필 (닉네임)
- 주간 목표 회수 변경 (2/3/4/5/6/7)
- 등록한 헬스장 (변경 가능)
- 그룹 초대 링크 생성/조회
- 로그아웃

## 6. 체크인 흐름

```
[오늘 헬스 감] 탭
    │
    ▼
GPS 위치 요청 (5초 타임아웃)
    │
    ├─ 성공 + 등록 헬스장 100m 이내
    │      → 메모 입력 (선택), 사진 첨부 (선택)
    │      → 저장: verification_method = 'gps'
    │
    └─ 실패 (권한 거부 / 타임아웃 / 100m 밖)
           → "위치 확인 실패. 사진으로 인증할까요?"
           → [카메라로 인증] 버튼
           → <input capture="environment"> 카메라 강제 실행
           → 촬영 → 업로드
           → 메모 입력 (선택)
           → 저장: verification_method = 'photo', photo_url 필수
```

**하루 여러번 허용:** 같은 날 여러번 체크인 가능. 각 체크인은 별개 row로 저장(메모/사진 각각 다르게). **단, 주간 달성률 계산 시에는 "며칠 갔는지"로 카운트** (하루 3번 가도 1일로 침).

**주 시작일:** 월요일 (매주 월요일 00:00 KST 기준 주간 리셋).

## 7. 온보딩 흐름 (첫 실행)

```
1. 이메일 입력 → 매직링크 발송 → 클릭 → 로그인
2. 닉네임 입력
3. 헬스장 이름 입력 → Naver 지역검색 → 후보 선택
   (현재 위치 권한 있으면 가까운 순 정렬)
4. 주간 목표 회수 선택 (기본 3회)
5. 초대 링크가 있으면 참여 / 없으면 새 그룹 만들기 / 나중에
6. 완료 → 오늘 탭
```

## 8. 그룹 로직

- **생성:** 아무나 그룹 생성 가능. 생성자가 관리자.
- **초대:** `https://<도메인>/join/<6자리코드>` 형태 링크. 만료 없음(관리자가 재발급 가능).
- **참여:** 링크 클릭 → 로그인(필요 시) → 참여 확인 → 그룹 추가.
- **다중 소속:** 한 사용자가 여러 그룹 소속 가능. 그룹 탭 상단 스위처로 전환.
- **탈퇴/추방:** 본인 탈퇴 가능. 관리자가 다른 멤버 추방 가능.

## 9. 데이터 모델 (Supabase Postgres)

```sql
profiles
  id                uuid PRIMARY KEY  -- auth.users(id) FK
  nickname          text
  weekly_goal       int               -- 주 목표 회수 (기본 3)
  gym_place_id      text              -- Naver 장소 ID
  gym_name          text
  gym_address       text
  gym_lat           double precision
  gym_lng           double precision
  created_at        timestamptz

groups
  id                uuid PRIMARY KEY
  name              text
  invite_code       text UNIQUE       -- 6자리 대문자+숫자
  created_by        uuid              -- profiles(id) FK
  created_at        timestamptz

group_members
  group_id          uuid              -- groups(id) FK
  user_id           uuid              -- profiles(id) FK
  joined_at         timestamptz
  PRIMARY KEY (group_id, user_id)

check_ins
  id                uuid PRIMARY KEY
  user_id           uuid              -- profiles(id) FK
  checked_in_at     timestamptz       -- 서버 시각
  local_date        date              -- 사용자 로컬(KST) 자정 기준 날짜 (주간 집계용)
  memo              text
  photo_url         text
  verification_method text            -- 'gps' | 'photo'
  lat               double precision  -- 감사용 (nullable)
  lng               double precision  -- 감사용 (nullable)
  -- UNIQUE 제약 없음: 하루 여러번 체크인 가능
```

**주간 달성률**은 애플리케이션 레이어에서 계산:
```
count(DISTINCT local_date
      FROM check_ins
      WHERE user_id = ?
        AND local_date BETWEEN [이번주 월요일] AND [이번주 일요일])
  / weekly_goal * 100
```
(DISTINCT로 하루 여러번 체크인해도 1일로 카운트)

## 10. 보안 (RLS 정책 요약)

- `profiles`: 본인만 UPDATE. SELECT는 같은 그룹 멤버까지 허용.
- `groups`: 멤버만 SELECT. 생성자만 UPDATE/DELETE.
- `group_members`: 본인 것 INSERT/DELETE. 그룹 멤버는 서로의 것 SELECT.
- `check_ins`: 본인만 INSERT/UPDATE/DELETE. 같은 그룹 멤버끼리 SELECT.
- `photo` 스토리지 버킷: 업로더만 쓰기. 같은 그룹 멤버만 읽기.

## 11. 에러 처리

| 상황 | 처리 |
|---|---|
| GPS 권한 거부 | 사진 인증 경로로 유도 |
| GPS 타임아웃(5초) | 사진 인증 경로 |
| 헬스장 100m 밖 | 현재 주소 표시 + "사진으로 인증할래요?" |
| 카메라 권한 거부 | 안내 메시지 + 브라우저 설정 링크 |
| 오프라인 | "인터넷 연결을 확인해주세요" 안내. 큐/재시도 없음 (단순화) |
| 하루 여러번 체크인 | 허용. 각각 별개 기록으로 저장. 주간 달성률은 일 단위 카운트 |
| 초대 링크 무효 | "링크가 유효하지 않아요" |
| Naver API 실패 | 재시도 버튼 + "잠시 후 다시" |

## 12. 테스트 전략

개인 프로젝트 규모에 맞게 최소한:

- **단위 테스트:** 거리 계산(Haversine), 주간 집계 함수, 로컬 날짜 계산
- **RLS 검증 스크립트:** 다른 사용자로 로그인 후 남의 데이터 접근 시도 → 거부되는지
- **수동 E2E:** iPhone Safari에서 실제 헬스장 방문 → 체크인 시나리오. 시뮬레이터는 GPS/카메라 없어서 부적합
- **E2E 자동화 없음** — 오버킬

## 13. 배포

- **개발:** `localhost:3000` (Naver API 도메인 등록 필요)
- **프로덕션:** Vercel 자동 배포. 기본 `https://<프로젝트명>.vercel.app`. 커스텀 도메인은 선택.
- **환경변수 (Vercel):**
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - `NAVER_CLIENT_ID` (서버 사이드 검색용)
  - `NAVER_CLIENT_SECRET` (서버 사이드 검색용)

## 16. 명시적으로 제외한 것

- 연속 출석(streak) 개념 → 주간 목표만 사용
- 사용자 검색/친구 추가 → 초대 링크만
- 갤러리 사진 업로드 → 카메라 촬영만
- 자동 백그라운드 체크인 → PWA 제약으로 불가
- 알림(푸시/이메일) → 그룹 탭 들어가야 확인
- 프로필 사진/아바타 → 닉네임만
- 여러 헬스장 등록 → 1개만 (변경 시 이전 것 대체)
- 오프라인 지원 → 온라인 필수
- 로컬 큐/재시도 → 없음
