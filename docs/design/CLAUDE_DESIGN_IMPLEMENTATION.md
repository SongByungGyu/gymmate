# GymMate 코발트 블루 UI 구현 지시서

## 목적

현재 구현되어 있는 GymMate 기능과 사용자 흐름은 유지하면서, 함께 전달한 `gymmate-cobalt-ui-reference.png`의 **시각적 방향**을 실제 코드에 적용한다.

Figma로 옮기는 작업은 하지 않는다. 이 문서와 참조 이미지를 기준으로 현재 코드베이스를 직접 분석하고, 공통 컴포넌트와 각 화면을 순차적으로 수정한다.

---

## 참조 자료 우선순위

서로 충돌하는 내용이 있으면 아래 우선순위를 따른다.

1. 현재 서비스의 기능, 데이터 흐름, 라우팅, 인증 로직
2. 이 문서의 명시적 요구사항
3. `gymmate-cobalt-ui-reference.png`의 색감, 여백, 컴포넌트 위계, 화면 분위기
4. 참조 이미지 안의 세부 문구나 임의 데이터

참조 이미지는 픽셀 단위로 복제하는 완성 시안이 아니라 **비주얼 레퍼런스**다. 현재 코드 구조와 실제 데이터에 맞게 재구성한다.

---

## 앱 성격

- 앱명: GymMate / 짐메이트
- 형태: 모바일 우선 PWA
- 주요 환경: iPhone Safari, 세로 화면
- 핵심 사용 시나리오: 친구 5~20명이 헬스장 출석을 공유하고 주간 목표 달성률을 확인
- 제품 성격: 전문 운동 분석 앱이 아니라 **친구끼리 쓰는 가벼운 운동 출석부**

사용자가 주요 화면에서 빠르게 확인해야 하는 것은 다음 네 가지다.

1. 나는 이번 주 몇 번 갔는가?
2. 오늘 체크인할 수 있는가?
3. 친구들은 오늘 갔는가?
4. 그룹에서 누가 목표를 잘 채우고 있는가?

## 절대 조건: 사진을 사용하지 않는다

이번 구현에서는 실사 사진, 운동 사진, 사용자 얼굴 사진, 스톡 이미지, 외부 이미지 URL을 사용하지 않는다.

참조 이미지에 사진이나 인물 일러스트가 보이더라도 구현하지 않는다.

### 대체 방식

- 사용자 프로필: 이름의 첫 글자 또는 최대 두 글자를 넣은 원형 이니셜 아바타
- 그룹 멤버: 서로 구분되는 옅은 단색 배경 + 진한 텍스트 이니셜
- 운동 인증 기록: 위치 아이콘, 카메라 아이콘, 체크 아이콘, 인증 방식 텍스트로 표현
- 사진 인증 흐름: 카메라 촬영 기능은 기존 요구대로 유지하되, 피드와 목록에는 사진 썸네일을 표시하지 않는다
- Empty state: 일러스트 없이 간단한 선형 아이콘 또는 기하학적 장식만 사용
- 앱 내부에 Unsplash, 랜덤 아바타, 외부 CDN 이미지를 추가하지 않는다

촬영 데이터 자체를 서버에서 반드시 제거하라는 뜻은 아니다. 현재 기능상 저장이 필요하면 유지하되, 이번 UI에서는 사진을 렌더링하지 않는다.

## 색상 시스템

코발트 블루를 브랜드 및 주요 행동 컬러로 사용한다.

```css
:root {
  --gm-primary: #2563EB;
  --gm-primary-hover: #1D4ED8;
  --gm-primary-pressed: #1E40AF;
  --gm-primary-soft: #EFF6FF;
  --gm-primary-soft-strong: #DBEAFE;

  --gm-success: #22C55E;
  --gm-success-soft: #F0FDF4;
  --gm-danger: #EF4444;
  --gm-danger-soft: #FEF2F2;

  --gm-text-primary: #17191F;
  --gm-text-secondary: #707580;
  --gm-text-tertiary: #9CA3AF;

  --gm-background: #F7F7F5;
  --gm-surface: #FFFFFF;
  --gm-border: #E7E7E2;
  --gm-border-strong: #D6D8DC;
}
```

### 색상 사용 규칙

- Primary: 메인 CTA, 활성 탭, 선택된 날짜/목표, 진행률
- Primary soft: 선택 배경, 안내 영역, 포커스 상태
- Success: 체크인 완료 상태에만 사용
- Danger: 오류와 로그아웃에만 사용
- 화면 전체를 파란색으로 채우지 않는다
- 한 화면에서 강한 파란색 면적은 메인 CTA 하나를 중심으로 제한한다
- 그라데이션은 사용하지 않는다

---

## 비주얼 원칙

1. 흰색과 따뜻한 회백색을 기반으로 한다.
2. 정보 위계는 색보다 타이포그래피와 여백으로 먼저 만든다.
3. 한 화면의 강한 Primary CTA는 최대 하나다.
4. 모든 영역을 카드로 감싸지 않는다. 리스트는 구분선과 여백을 우선한다.
5. 카드 안에 카드를 넣지 않는다.
6. 그림자는 기본적으로 사용하지 않는다. 필요한 경우 매우 약한 한 단계만 사용한다.
7. 기본 모서리 반경은 14px, 큰 surface는 최대 16px로 제한한다.
8. 원형 프로그레스 링과 과도한 통계 대시보드를 사용하지 않는다.
9. 3D 아이콘, 이모지 아이콘, 캐릭터 일러스트를 사용하지 않는다.
10. 아이콘은 Lucide 또는 Heroicons 중 현재 프로젝트에 더 자연스럽게 맞는 한 세트로 통일한다.
11. 문구는 실제 서비스처럼 짧고 직접적으로 작성한다.
12. iOS safe area와 터치 영역을 고려한다.

### 타이포그래피

Pretendard가 이미 적용되어 있으면 유지하고, 없으면 시스템 한글 폰트 스택을 사용한다. 새로운 무거운 폰트 의존성은 추가하지 않는다.

```text

섹션 제목: 18px / 700
핵심 수치: 24px / 700
본문: 16px / 500
보조 텍스트: 14px / 400
탭 및 캡션: 12~13px / 600
```

## 공통 컴포넌트

먼저 공통 컴포넌트와 토큰을 정리한 뒤 각 화면에 적용한다.

### Button

- Primary: 코발트 블루 배경, 흰색 텍스트, 높이 56px, radius 14px
- Secondary: 흰색 배경, border, 진한 텍스트
- Ghost: 배경 없이 Primary 텍스트
- Danger: 기본은 흰색 또는 danger-soft 배경, 빨간 텍스트/테두리
- disabled: 채도와 대비를 낮추되 텍스트 가독성 유지
- 아이콘과 텍스트 간격 8px

### Input

- 높이 52~56px
- 배경 흰색
- 기본 1px border
- focus 시 코발트 블루 테두리 또는 2px focus ring
- label, helper, error 메시지의 수직 간격 일관성 유지

### Avatar

- 실사 이미지 금지
- 32px, 40px 두 크기 우선
- 이름의 첫 글자 또는 최대 두 글자
- 동일 사용자에게 같은 배경색이 유지되도록 이름 기반 색상 선택 함수를 사용
- 배경은 옅고 텍스트는 진하게

### Progress

- 높이 6~8px
- 트랙은 연한 회색
- 채움은 코발트 블루
- 퍼센트와 횟수는 오른쪽 텍스트로 제공
- 애니메이션은 200~300ms 정도의 짧은 width transition만 사용

### List Row

- 카드 대신 기본적으로 평평한 행 + 구분선
- 제목, 보조정보, 우측 값/chevron의 3단 위계
- 최소 터치 영역 44px 이상

### Bottom Tab Bar

- 오늘 / 캘린더 / 그룹 / 설정
- iOS safe area 포함
- 흰색 surface와 상단 border
- 활성 탭만 코발트 블루
- 비활성 탭은 muted gray
- 각 탭 아이콘과 텍스트의 수직 간격을 작게 유지
- 떠 있는 pill 형태로 만들지 않는다

## 화면별 구현 방향

### 로그인 `/login`

- 로고와 GymMate 텍스트는 작고 단정하게
- 긴 설명이나 일러스트 사용 금지
- 이메일 필드 1개
- `로그인 링크 받기` Primary CTA 1개
- 발송 후에는 같은 화면 안에서 아이콘 + 짧은 안내 블록으로 상태 변경

### 온보딩 `/onboarding`

- 한 화면에 한 질문
- 상단에 `1 / 3`, `2 / 3`, `3 / 3`
- 하단에 고정된 `다음` 또는 `완료` 버튼
- 닉네임 입력, 헬스장 등록, 주간 목표 선택의 패턴을 일관되게 유지
- 헬스장 좌표 숫자는 일반 화면에 노출하지 않는다
- GPS 성공 시 `등록한 헬스장명`과 완료 아이콘만 표시

### 오늘 `/today`

가장 중요한 화면이다.

권장 구조:

1. 상단 인사말 + 알림 또는 간단한 우측 액션
2. `이번 주 3 / 5회`와 7일 출석 레일
3. 큰 `오늘 헬스 감` CTA
4. 오늘 먼저 체크인한 친구 목록
5. 최근 인증 리스트

주의:

- 통계를 여러 개의 큰 카드로 쪼개지 않는다
- 체크인 CTA가 화면에서 가장 강해야 한다
- 최근 인증에 사진 썸네일을 사용하지 않는다
- 인증 방식은 `GPS 인증`, `사진 인증`처럼 텍스트와 아이콘으로 구분한다
- 같은 날 여러 기록이 있으면 시간순 리스트로 표시한다

### 캘린더 `/calendar`

- 월요일 시작
- 일반 날짜는 평평한 셀
- 오늘은 얇은 코발트 테두리 또는 텍스트 강조
- 체크인한 날짜는 작은 코발트 도트 또는 옅은 배경
- 선택 날짜는 채워진 코발트 원 또는 rounded square 중 하나로 통일
- 날짜 선택 시 캘린더 아래의 상세 리스트 또는 bottom sheet에 기록 표시
- 사진은 표시하지 않는다

### 그룹 `/groups`

- 상단 그룹명 + 스위처
- 초대 링크는 큰 카드보다 `초대 링크 / 복사` 한 줄 메뉴 형태
- 멤버별 주간 달성률은 작은 아바타 + 이름 + `3 / 5회` + 진행바
- 각 멤버를 큰 카드로 만들지 않는다
- 최근 활동은 평평한 리스트
- 방장 액션은 각 행의 `···` 메뉴에 숨긴다
- 삭제/추방은 즉시 실행하지 말고 기존 확인 흐름을 유지한다

### 그룹 없음

- 가운데 정렬된 간단한 그룹 아이콘
- `아직 참여한 그룹이 없어요`
- `새 그룹 만들기` Primary CTA
- `초대 링크가 있나요?` Ghost 액션
- 캐릭터 일러스트나 사진 사용 금지

### 새 그룹 `/groups/new`

- 뒤로가기
- 화면 제목
- 그룹 이름 입력
- 하단 또는 자연스러운 위치에 `만들기` Primary CTA
- 부가 설정을 추가하지 않는다

### 초대 링크 `/join/[code]`

- 초대받은 그룹명
- 한 줄 설명
- 로그인 상태에 따라 로그인 또는 참여 CTA 하나
- 사진이나 축하 일러스트 없이 아이콘과 텍스트만 사용

### 설정 `/settings`

- iOS 설정처럼 섹션형 리스트
- 프로필, 주간 목표, 헬스장, 그룹, 로그아웃
- 각 항목을 개별 대형 카드로 만들지 않는다
- 로그아웃은 화면 맨 아래에서 danger style

### 체크인 상태 `check-in-flow.tsx`

기능 로직은 유지하고 시각 표현만 통일한다.

- idle: Primary CTA + 선택 메모
- gps: spinner + `위치를 확인하고 있어요`
- photo-required: 카메라 아이콘 + `사진으로 인증하기`
- saving: spinner + `저장하고 있어요`
- done: success 아이콘 + `체크인 완료`
- error: danger 아이콘 + 짧은 오류 문구 + `다시 시도`

사진 촬영 기능이 필요한 경우 카메라는 열 수 있지만, 완료 화면과 활동 리스트에는 썸네일을 렌더링하지 않는다.

## 작업 절차

1. 현재 코드베이스와 라우트, 컴포넌트, 데이터 흐름을 먼저 분석한다.
2. 변경 전 `npm`/`pnpm`/`yarn` 중 프로젝트가 사용하는 패키지 매니저를 확인한다.
3. 현재 기능을 깨뜨리지 않는 구현 계획을 먼저 짧게 제시한다.
4. CSS 변수 및 공통 컴포넌트를 우선 정리한다.
5. 오늘 탭 → 하단 탭 → 체크인 흐름 → 그룹 → 나머지 화면 순으로 적용한다.
6. 320px, 375px, 428px 너비에서 레이아웃을 확인한다.
7. 가능한 경우 Playwright 또는 프로젝트의 기존 테스트 도구로 주요 화면 스크린샷을 생성한다.
8. lint, typecheck, test, production build를 실행한다.
9. 실패 항목이 있으면 원인과 미해결 사항을 정확히 보고한다.
10. 마지막에 변경 파일, 주요 디자인 결정, 검증 결과를 요약한다.

## 금지 사항

- 기존 인증, DB, API, 체크인 판정 로직을 디자인 편의를 위해 변경하지 않는다
- 기능을 임의로 삭제하지 않는다
- 외부 이미지 서비스나 스톡 이미지를 추가하지 않는다
- 사진 썸네일 UI를 새로 만들지 않는다
- Figma 파일 생성을 작업 목표로 삼지 않는다
- 모든 화면을 한 번에 임의 재작성하지 않는다
- 새로운 대형 UI 라이브러리를 함부로 추가하지 않는다
- 기존 패키지로 가능한데 불필요한 의존성을 추가하지 않는다
- 참조 이미지의 오탈자, 인물 사진, 임의 데이터까지 복제하지 않는다

## 완료 기준

- 기존 주요 기능과 라우트가 정상 동작한다
- Primary 컬러가 `#2563EB`로 일관되게 적용된다
- 사진이나 외부 이미지가 화면에 렌더링되지 않는다
- 모든 사용자 표시는 이니셜 아바타로 통일된다
- 오늘 탭의 핵심 CTA가 명확하다
- 그룹 멤버 진행률을 한눈에 파악할 수 있다
- 하단 탭이 iPhone safe area를 침범하지 않는다
- 320~428px 너비에서 가로 스크롤이 없다
- lint/typecheck/build 결과가 보고된다
- 변경된 UI의 주요 화면을 스크린샷으로 확인할 수 있다
