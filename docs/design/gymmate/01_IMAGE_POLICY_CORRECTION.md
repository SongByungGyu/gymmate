# GymMate 이미지 사용 정책 — 정정본

## 정정 배경

이전 지시의 "사진을 사용하지 않는다"는 표현은 잘못된 요구사항이다. 정확한 의도는 다음과 같다.

> **사용자나 그룹 멤버의 인물 프로필 사진은 사용하지 않고, 사람은 닉네임 텍스트만으로 표시한다. 그 외 앱 이미지와 실제 체크인 사진은 정상적으로 사용한다.**

이 문서는 기존의 모든 `no-photo`, `no-image`, `사진 미사용`, `이니셜 아바타로 대체` 지시보다 우선한다.

---

## 1. 반드시 표시해야 하는 이미지

### 체크인 인증 사진

사진 인증으로 저장된 실제 운동/헬스장 사진은 다음 위치에 표시한다.

- 오늘 탭의 오늘 기록 또는 최근 기록
- 캘린더에서 날짜를 선택했을 때의 상세 기록
- 그룹 탭의 최근 활동 피드
- 사진 인증 완료 직후의 결과 화면에 기존 UX가 있다면 유지

표시 규칙:

- 실제 사진 URL이 있을 때만 썸네일을 표시한다.
- 썸네일을 누르면 원본 비율을 유지한 확대 보기 또는 lightbox를 제공한다.
- 목록 썸네일은 `object-fit: cover`를 사용한다.
- 원본 확대 화면은 `object-fit: contain`을 사용한다.
- 로딩 중에는 레이아웃이 흔들리지 않도록 고정된 aspect ratio를 둔다.
- 이미지 로드 실패 시 전체 행을 깨뜨리지 말고 짧은 오류 상태와 다시 시도 동작을 제공한다.
- 사진의 업로드/저장/조회 로직은 기존 기능을 그대로 보존한다.

### 앱의 일반 이미지

아래 이미지는 사용할 수 있다.

- GymMate 로고
- PWA 앱 아이콘
- 카메라, 위치, 체크, 캘린더 등 SVG 아이콘
- 서비스에 이미 존재하는 장식용 이미지 또는 일러스트
- empty state용 비인물 일러스트
- 디자인 참고 이미지

단, 화면 목적과 관계없는 스톡 사진을 새로 추가하지 않는다.

## 2. 사용하지 않는 이미지

### 사용자 및 그룹 멤버의 프로필 사진

다음은 표시하지 않는다.

- 사용자 얼굴 사진
- SNS/이메일 계정에서 가져온 프로필 사진
- 랜덤 아바타 서비스 이미지
- AI 생성 인물 사진
- 멤버별 캐릭터 초상
- 이니셜 원형 아바타
- 이름 첫 글자를 넣은 컬러 배지

사람을 표시할 때는 **닉네임 텍스트만 사용한다.**

예시:

```text
운동러님 · 오후 7:32
GPS 인증
```

```text
헬창형                          4 / 5회
━━━━━━━━━━━━━━━━━━
```

닉네임 옆에는 필요할 경우 방장, 나, 목표 완료 같은 작은 텍스트/상태 배지만 사용할 수 있다. 사람을 대신하는 원형 이미지 영역은 만들지 않는다.

## 3. 인증 방식별 표시 규칙

### 사진 인증 기록

```text
운동러님                         오후 7:32
사진 인증 · 하체 완료
[실제 체크인 사진 썸네일]
```

- 사진이 실제로 존재하면 표시한다.
- 닉네임 영역에 프로필 사진이나 아바타를 붙이지 않는다.

### GPS 인증 기록

```text
운동러님                         오후 7:32
위치 인증 · 바디팩토리 강남점
오늘은 하체
```

- 사진이 없으므로 이미지 placeholder를 표시하지 않는다.
- 행의 높이는 콘텐츠에 맞게 자연스럽게 줄어들어야 한다.

### 사진 URL은 있지만 로드에 실패한 기록

- 회색 빈 박스를 영구 표시하지 않는다.
- `사진을 불러오지 못했어요`와 `다시 시도`를 작은 영역에 표시한다.
- 개발 환경에서는 실패 URL과 상태 코드를 확인할 수 있도록 로그를 남긴다.

## 4. 구현 시 기술 점검

이미지가 보이지 않는 문제를 스타일로 덮지 말고 데이터 흐름을 끝까지 확인한다.

### 데이터

- 촬영 후 업로드 요청이 실제로 성공하는지
- DB/API에 사진 경로 또는 URL이 저장되는지
- 목록 API 응답에 사진 필드가 포함되는지
- 서버의 snake_case와 프론트의 camelCase 변환이 일치하는지
- signed URL을 사용한다면 만료 전에 재발급되는지

### Next.js

- `next/image`를 사용한다면 현재 스토리지 호스트만 `images.remotePatterns`에 허용한다.
- 보안을 위해 `hostname: '**'` 같은 전체 와일드카드는 추가하지 않는다.
- 로컬 blob preview와 영구 URL을 혼동하지 않는다.
- 이미지의 width/height 또는 `fill` 부모 크기가 유효한지 확인한다.

### CSS

- 부모 요소에 실제 높이 또는 aspect ratio가 있는지
- `overflow-hidden`이 이미지를 0 크기로 자르지 않는지
- 텍스트 레이어나 skeleton이 이미지를 덮고 있지 않은지
- 모바일에서 썸네일이 화면 밖으로 밀리지 않는지 확인한다.

### 보안과 개인정보

- 기존 권한 정책과 인증된 URL 방식을 유지한다.
- 다른 그룹의 비공개 체크인 사진이 노출되지 않도록 기존 접근 제어를 우회하지 않는다.
- 이미지 문제를 해결하기 위해 스토리지 버킷 전체를 무조건 public으로 바꾸지 않는다.

---

## 5. 완료 기준

다음 조건을 모두 만족해야 한다.

- 사진 인증 기록을 생성할 수 있다.
- 업로드 직후 해당 사진이 보인다.
- 새로고침 후에도 사진이 보인다.
- 오늘 탭에서 체크인 사진이 보인다.
- 캘린더 날짜 상세에서 체크인 사진이 보인다.
- 그룹 최근 활동에서 체크인 사진이 보인다.
- 사진을 누르면 확대해서 볼 수 있다.
- GPS 인증 기록에는 불필요한 빈 이미지 칸이 없다.
- 모든 사람은 프로필 사진/아바타 없이 닉네임 텍스트만으로 표시된다.
- 코발트 블루 UI와 기존 인증·그룹·체크인 기능이 유지된다.
